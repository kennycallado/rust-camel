# Changelog

## Unreleased

### Added

- feat(components/jms): durable topic subscribers end to end — `clientId`/`subscriptionName` URI parameters (snake_case aliases, pair-required, topic-only, `concurrentConsumers=1`), `client_id`/`subscription_name` on `SubscribeRequest`, and the fail-closed `durable-subscribers-v1` startup/attach capability gate; the bridge pins Artemis `verifyHost=true` explicitly for secure schemes (2.36 connector default, now explicit), and the JMS READMEs document the durable contract plus a Classic `ssl://` example (bd rc-c4fbo).
- feat(testing): scenario documents accept a document-level `finally:` teardown list (sleep, sql, surreal, and a delete-only redis `del` prepare action) that runs after the verdict on both verdict paths; teardown failures report as the new `teardown-failure` apparatus class without masking the verdict (bd rc-6wodc).
- feat(builder): first-class `Layer` middleware around steps and routes — `ProcessorLayer` is an object-safe processor factory with a blanket impl for tower layers whose service is `Clone + Send + Sync`, carried into the builder at producer, section, and route granularity via `LayerFactory`; boxed `CamelError`s pass through unchanged and `Timeout`/`Buffer` failures arrive typed through the elapsed source chain, with a guide chapter and example crate (bd rc-s5ezy).
- feat(testing): scenario documents declare `namespaces` — `[{bindVar, base}]` entries mint per-run `BASE~it~RUN~ORD~` keys into the harness-provisioned environment layer (prefix-free by trailing separator and fixed widths), and the finally-only redis `unlinkPrefix` action must bind to a declared namespace, re-checks the resolved value and every scanned key byte-for-byte, escapes globs, and batches `UNLINK`s (500 per batch, 10 s deadline, 100k cap) with a breach reported as `teardown-failure`; `FLUSHDB` and non-namespace prefixes stay forbidden (bd rc-ql8eq).
- feat(cron): numeric day-of-week translates Unix 0/7=Sunday and 1=Monday into the crate's 1-7 ordinals instead of passing through unchanged — names and stepped wildcards keep their meaning, and mixed name/numeric endpoints are rejected as ambiguous (bd rc-fa4sd).
- feat(components/jms): the Artemis fixture observes broker-side poison disposition — `artemis queue stat` via docker exec with fail-closed parsing (an absent query never becomes zero counts), so the poison case asserts acknowledged-and-removed or records native evidence, closing the unobserved gap in the living docs and ADR-0067 (bd rc-5c6yv).

### Changed

- change(deps): surrealdb 3.2.4 → 4.0.0 clears RUSTSEC-2026-0453 (KV use-after-free via affinitypool) and RUSTSEC-2026-0454 (reblessive Send/Sync); workspace requirement moves "3" → "4" with the same feature set, zero component code changes, cargo audit now vulnerability-free (bd rc-yhpyz).
- change(components/http,rest-dsl): non-request-borne type-conversion failures now map to HTTP 500 (conversion_failed) instead of 400 (bad_request), and the REST binding-injected unmarshal/schema check reclassifies its failures to ValidationError (400, validation_error) per ADR-0096 fault blame; mid-route user unmarshal and authored marshal keep their conversion error identity but now report 500; metric label at the binding seam moves type_conversion → validation; no opt-in window (ADR-0090) (bd rc-zwd3l).

### Fixes

- fix(components/jms): a broker-rejected JMS property write now fails the send with a typed error naming the offending property names (no values), mapped to gRPC INVALID_ARGUMENT — a hyphenated, allowlisted header such as `x-crash-proof` no longer silently vanishes on Artemis; legal-name forwarding is byte-identical (bd rc-ooczk).
- fix(cli): sealed artifacts boot without a writable system temp directory for the xslt, xsd, and sql asset classes (in-memory resolution), and the TLS classes fall back to a writable artifact-adjacent directory with a typed error when none exists (bd rc-l39dj).
- fix(components/http): a route that sets `Content-Type` now always emits it verbatim on the reply, including when it equals the request value — inheritance is tracked by the `CamelHttpContentTypeInherited` provenance marker that route header writes clear, replacing value equality; replies to requests with a `Content-Type` whose route only rewrites the body no longer emit a request-dependent inferred type, and archive/stream fragment replies and `useOriginalMessage` restorations no longer depend on the request value either (bd rc-tf0k4).
- fix(languages/simple): interpolating a `Bytes` body as a direct `${body}` slot into a template string with literal text now renders valid UTF-8 as text instead of a byte list, and fails with a `conversion` error on invalid UTF-8; a bare `${body}` keeps the byte array (bd rc-0v855).
- fix(languages/rhai): a JSON integer above i64::MAX in a header, property, or body no longer fails every later rhai script step — it binds as a json number carrying the exact decimal token, and fails only later, at the operation, if used in a refused comparison or converted outbound as a non-image token (bd rc-141om).
- fix(components/mail): with one account and no `?account=`, an endpoint no longer logs in to an unlisted host — it needs the URI host in the account's `allowedHosts` (case-insensitive), fails at endpoint creation when the list is empty, the host does not match or the URI has no host, and never carries the host in the error; migrate with `?account=<name>` or `allowedHosts` (bd rc-bcstf).
- fix(components/sql): batch positions can no longer reinterpret numeric bits — sqlx keyed its statement cache by SQL text alone and fixed parameter types at the first Parse, so a batch row binding `i64` after one binding `f64` silently reinterpreted 8 bytes (an external report stored 20 as 1e-322 and 6.5 as 4.6e18 with no error); every position now binds one wire encoding per statement — the server-described type when the probe yields one, otherwise a per-batch float-wins scan in its own cache namespace — so mixed-kind batches store exact values and homogeneous batches are unchanged (bd rc-fef4z).
- fix(components/sql): undecodable `Any` columns fail loudly with a typed error naming the column, the driver-reported type, and the CAST workaround (double precision or text for NUMERIC/DECIMAL, text otherwise) instead of sqlx's raw "Any driver does not support the Postgres type"; `row_to_json` no longer substitutes null for non-finite floats, non-UTF-8 BYTEA, or undecodable columns, `REAL` columns decode as JSON numbers, and streaming bodies (`StreamList`, `useIterator`) surface the same typed error instead of wrapping it; the decoded-type matrix — including that SQL NULL stays null only for the types the driver supports, and that CHAR/BIT types need a CAST — is documented in the README and the database guide (bd rc-s7lb0).
- fix(components/sql): drop the `connect_timeout` URL key sqlx ignores — enrichment appended `connect_timeout=10` to every database URL, but sqlx-postgres 0.9 has no such key and logged "ignoring unrecognized connect parameter" on every pool creation while no connect timeout applied; the pool `acquire_timeout` (30 s default) remains the real bound and is now documented, and operator-supplied keys are left untouched (bd rc-sa1zo).
- fix(builder): `.parameters()` targets a layered `to()` — `LayeredTo` is endpoint-bearing, but the call-time gate and parameter application only knew To/WireTap/Enrich/PollEnrich, so `.parameters()` after `.to_layered()` failed with a false "no pending endpoint step"; it now rewrites the endpoint URI like To (bd rc-vf7vu).
- fix(core): runtime registration errors carry a single `invalid state:` prefix — the payload was wrapped twice, rendering "invalid state: invalid state: Component not found"; the command layer renders the `InvalidState` payload verbatim and the public registration path converts to RouteError without a second wrap (bd rc-uqwy2).
- fix(core): an Explicit consumer that exits without a background handle is always reported — the warning fired only when readiness was never signalled, so consumers that called `mark_ready()` stopped right after `start()` and vanished silently; the warning now fires for every no-handle completion before cancellation, and docs state that readiness does not extend the lifetime (bd rc-4uuy8).
- fix(components/jms): a rejected forwarded property no longer rides the transport path — the bridge's `INVALID_ARGUMENT` for an illegal header is now a plain processor error, so a caller mistake stops emitting the "JMS send transport error" warn and rebuilding the channel (process lock) on every send; transport failures keep their prefix and refresh behaviour unchanged (bd rc-qpkok).
- fix(components/jms): the native pool-evictor verifier builds from a closed classpath — linking its image over the application runtime classpath pulled Quarkus Graal substitutions into the analysis and died on shaded netty and smallrye-common-net; it now links only the two pool implementations, the JMS API, and its own stubs, rejects any quarkus jar or the Artemis uber-jar, and runs on the JVM leg too (bd rc-qk18y).
- fix(languages/rhai): limit errors name the limit and the bound (`<limit> <bound> exceeded`) for operations, string/array/map size, call levels, and the execution timeout; depth errors name both candidate limits because rhai raises one shared variant; error categories and value redaction are unchanged (bd rc-53uro).
- fix(cli): the `integration-http` feature combination builds again — `FakeDevTarget` used a bare `Arc` under that feature where the file had no `std::sync::Arc` import; both sites are now fully qualified (bd rc-pc71e).
- fix(test-support): `capture_warns` captures `error!` records again — the level comparison was inverted (tracing orders `Level` inverted), capturing everything except errors, and no consumer relied on the over-capture; a scenario action without a datasource catalog now reports what the author must do instead of the internal caller contract, and an unresolvable llm `base_url` no longer aborts boot (resolution runs at first use, still fail-closed before any connection) (bd rc-icpbt, rc-oheej, rc-ga0kl).
- fix(components/http): redirect failures name the parameter — 301/302/303/307/308 failures append "(redirect not followed; set followRedirects=true)" when the flag is off, with the URL still redacted (ADR-0051), and the component docs stop claiming the producer follows redirects (`followRedirects` defaults to false, so a 3xx surfaces as a failed exchange) (bd rc-qt54d).

### Performance

- perf(languages/rhai): write-back change detection compares values natively instead of compiling a script expression per scalar leaf, and each evaluation holds one snapshot and one working copy per container — multi-thousand-entry properties no longer cost hundreds of thousands of script compilations per mutating eval (bd rc-m01r9).
