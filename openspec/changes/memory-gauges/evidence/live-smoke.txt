  tick; allocated moved 2350840 -> 3338224 -> 2776496 across the run.

Notes
-----
- No live TLS server was needed: the pinned-cache families are emitted on the
  DNS-pin path (ssrf::resolve_initial_url_for_ssrf -> PinnedClientCache::
  get_or_build) during resolution/client-selection, BEFORE the connection is
  attempted — connection-refused on the closed target ports does not affect
  the counters. Both component labels (camel-http, camel-https) are live here,
  so no fallback to unit-test-only evidence was required. Unit provenance:
  crates/components/camel-http/src/client_cache.rs #[cfg(test)] tests.
- Config gotcha discovered while wiring: when Camel.toml contains a [default]
  profile table, apply_profile keeps ONLY [default] — a top-level
  [observability.prometheus] table is silently dropped (camel-config
  config.rs apply_profile). The exporter must be nested under the profile
  ([default.observability.prometheus]).
