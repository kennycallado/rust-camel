### T1: Classify finished delegate task errors

Files: crates/components/camel-master/src/supervision.rs, crates/components/camel-master/src/tests.rs, crates/components/camel-master/src/tests/delegate_errors.rs, crates/components/camel-master/src/tests/stale_stamp.rs, crates/components/camel-master/src/tests/acquisition_budget.rs, crates/components/camel-master/README.md, crates/camel-test/tests/support/master_probe.rs (doc comment at line 21 only).

Steps:
1. Add the test knob as one enum plus one field. In tests.rs add `#[derive(Clone)] enum ConsumerFault { StartError(CamelError), ErrorOnCancel(CamelError) }`. Give `ErrorDelegateComponent`, `ErrorDelegateEndpoint` and `SuccessDelegateConsumer` a field `first_consumer_fault: Option<ConsumerFault>` (component and endpoint carry it through; the consumer owns it), default `None` at every existing construction site: tests.rs, tests/stale_stamp.rs (~line 155) and tests/acquisition_budget.rs (~line 233). `ErrorDelegateEndpoint::create_consumer` hands the fault to the consumer created at ordinal 1 (`call_idx == 1`) only. `SuccessDelegateConsumer::start`: if its fault is `StartError(err)`, return `Err(err)` as its first statement, before `context.send`; if it is `ErrorOnCancel(err)`, send "ok", `context.cancelled().await`, then return `Err(err)`. Add `build_start_error_master(platform_service, create_endpoint_calls, create_consumer_calls, first_consumer_fault, max_attempts, metrics) -> MasterConsumer`, a copy of `build_error_delegate_master_with_metrics` that sets the field. Add `fn start_error_events(metrics: &RecordingMetricsCollector, reason: &str) -> usize` next to `lifecycle_events`: it counts `counters_named("master_delegate_lifecycle_total")` entries whose labels equal `expected_lifecycle_labels("start_error", reason)`.
2. Write the three tests below in delegate_errors.rs. Run them against unmodified production code and record the red output.
3. In supervision.rs, restructure the finished-handle branch of the retry tick (today a let-chain `matches!(&state, DelegateState::Active { handle, .. } if handle.is_finished()) && let Err(err) = stop_delegate(..).await`). Declare `let mut fatal: Option<CamelError> = None;` inside the inner `async` block, before `loop`. New branch: when the active handle is finished, first `if stop_token_loop.is_cancelled() || context.is_cancelled() { break; }`; then `match stop_delegate(..).await`: on `Ok(())` do nothing (unchanged); on `Err(err)` with `is_retryable_camel_error(&err)` call `emit_lifecycle(rctx.metrics, rctx.lock_name, rctx.route_id.as_str(), "start_error", "transient")`, set `tick_err = Some(err)` (declare `let mut tick_err: Option<CamelError> = None;` as the first statement of the `retry_tick` arm, so it never outlives the tick) and warn (call `warn!` with `error = %err` before moving `err` into `tick_err`); on any other `Err(err)` call `emit_lifecycle(.., "start_error", "permanent")`, log with `error!` preceded by the comment `// log-policy: system-broken`, set `fatal = Some(err)` and `break`. In the acquisition branch, where `!rctx.reconnect.should_retry(attempts)` today only warns and `break`s, set `fatal = tick_err.take()` before the `break` (the budget refusal for a delegate task failure always happens in the tick that observed the failure, because the retry runs in the same tick; a `None` stays `None`, so construction-error exhaustion keeps its `Ok`). After the loop, capture `let tail = stop_delegate(..).await;` (no `?`), then run `let _ = timeout(drain_timeout, leadership_handle.step_down()).await;`, then return `match (fatal, tail) { (Some(err), _) => Err(err), (None, Err(err)) => Err(err), (None, Ok(())) => Ok(()) }`; keep the `Ok::<(), CamelError>` type on the block.
4. Keep `stop_propagates_delegate_start_error` and `explicit_delegate_background_failure_propagates` green. Both use a start error without a transient marker, so both are permanent and `stop()` still sees `ended_before_stop`. Re-run them after step 3.
5. Document the classification, the budget behavior of run failures, and the `start_error` event (it also covers run failures) in crates/components/camel-master/README.md, and add `start_error` to the event list in the doc comment of master_probe.rs.
6. Run the complete camel-master suite, `cargo test -p camel-test` master tests, `cargo clippy -D warnings`, and the lints from AGENTS.md. Request review and resolve every critical or important finding.
