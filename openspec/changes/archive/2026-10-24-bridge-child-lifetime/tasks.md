### Task 1.2: Watchdog + GroupGuard module (`src/group.rs`)

**Files:**
- `crates/services/camel-bridge/src/group.rs` (new)
- `crates/services/camel-bridge/src/lib.rs` (modified — `mod group;` + `pub(crate) use`)
- `crates/services/camel-bridge/src/process.rs` (modified — add `BridgeError::Supervision(String)` variant to the existing `BridgeError` enum)

**Steps:**
1. Add `#[cfg(unix)] pub(crate) mod group;` to `src/lib.rs`.
2. In `src/group.rs` (entire module `#[cfg(unix)]`) define `pub(crate) const WATCHDOG_SCRIPT: &str = "trap \"\" TERM; while read -r _; do :; done; kill -KILL -0";` — the arming build wraps it as `format!("trap \"\" TERM; printf '\\001' >&{ack_fd}; {WATCHDOG_SCRIPT}")` so the post-trap acknowledgement byte is written before the read loop (TERM delivered any time after exec is ignored; the fork-to-trap window is closed by the ack: the parent does not accept arming until the ack byte arrives, which can only be written after `trap` executed).
3. Define `pub(crate) struct GroupGuard` backed by `Arc<GroupShared>` where `GroupShared` holds `pgid: std::sync::Mutex<Option<i32>>`, `write_end: std::sync::Mutex<Option<std::os::fd::OwnedFd>>`, `watchdog: std::sync::Mutex<Option<tokio::process::Child>>`, `bridge: std::sync::Mutex<Option<tokio::process::Child>>`, and `cleanup_exec: std::sync::Mutex<()>` (sync mutex — the ENTIRE cleanup sequence is synchronous and runs either on the monitor thread, inside `tokio::task::spawn_blocking` from async `stop()`, or inside `Drop`; no cleanup mutex guard is ever held across an await, so no Send problems). ALL group signals and reaps execute inside `GroupShared`'s sync cleanup method under `cleanup_exec` — `stop()`, monitor cleanup requests, and `Drop` funnel through the same path. Single owner, no signal after invalidation. Supervision is RUNTIME-INDEPENDENT: the monitor and its cleanup run on a dedicated `std::thread`, so dropping or shutting down the caller's tokio runtime never disarms supervision.
4. Implement `GroupGuard::establish() -> Result<Self, BridgeError>` as `Self::establish_with_program("sh")`, with `establish_with_program(program: &str)` as the real body so tests can inject a failing program. Body: create the liveness pipe close-on-exec — on Linux `libc::pipe2(&mut fds, libc::O_CLOEXEC)` (atomic); on macOS (no pipe2) `libc::pipe()` + `fcntl(fd, libc::F_SETFD, libc::FD_CLOEXEC)` on both ends, executed while holding a process-wide `static PIPE_SPAWN_LOCK: std::sync::Mutex<()>` shared by ALL `establish_with_program` calls, so no camel-bridge spawn can interleave between `pipe()` and `fcntl` (documented residual: a foreign spawn from an unrelated thread inside that window could observe the transient fd — accepted, not exercised by tests). Create the ack pipe identically under the same lock. Spawn the watchdog via `tokio::process::Command::new(program)` with `arg("-c")`, the armed script (ack write end passed as a dup2'd fd number baked into the script string), stdin = liveness read end (converted via `std::fs::File` so the stdio dup clears CLOEXEC on installed fd 0), stdout/stderr `Stdio::null()`, and `unsafe { cmd.pre_exec(move || libc::setpgid(0, 0)) }` (watchdog = its own group leader). Arming verification (bounded 2 s): read ONE byte from the ack read end (post-trap readiness acknowledgement — timeout or EOF fails closed), then `libc::getpgid(wd_pid) == wd_pid` and `libc::kill(wd_pid, 0) == 0`; close the ack write end after the ack byte (so later watchdog death cannot be masked by an open ack pipe). Any failure aborts with `BridgeError::Supervision` and drops all pipe ends (no bridge exists yet). Return the guard with `pgid: Some(wd_pid)`.
5. Implement `GroupGuard::spawn_bridge(mut cmd: tokio::process::Command) -> Result<(), BridgeError>`: acquire `cleanup_exec` FIRST (same async mutex as cleanup — serializes spawn against invalidation/reaping), then verify the watchdog is EXECUTION-live with a NON-REAPING check — `waitid(P_PID, wd_pid, &mut siginfo, libc::WEXITED | libc::WNOHANG | libc::WNOWAIT)` returning "exited" fails closed (a zombie watchdog answers `kill(pid,0)` with 0, so a signal-probe check would wrongly accept a dead leader; `waitid` sees the exit while leaving it waitable), and `pgid` must still be `Some` — then add `unsafe { cmd.pre_exec(move || libc::setpgid(0, PGID)) }` (child-side join before exec; a failed join aborts the spawn), spawn the bridge child into `GroupShared.bridge`, release the lock, return `Supervision` error on failure. The check no longer depends on monitor timing: even before the monitor's cleanup fires, the zombie-dead watchdog is rejected.
6. Implement the monitor as a DEDICATED `std::thread` owned by the guard (NOT a tokio task — runtime shutdown must never disarm supervision): loop every 100 ms — `libc::waitid(P_PID, wd_pid, &mut siginfo, libc::WEXITED | libc::WNOHANG | libc::WNOWAIT)` (non-reaping) plus `Weak::upgrade` on `GroupShared`; when the watchdog exit is observed AND the guard still lives, run the serialized sync cleanup path directly on this thread and log `tracing::error!("bridge watchdog exited early; group cleaned")` (log-policy: system-broken) once. The thread holds a `Weak<GroupShared>` clone and its pid — NO write end, NO child handles, NO strong reference; it exits when the upgrade fails (guard dropped) or a `stop flag` (AtomicBool in GroupShared) is set by cleanup. For TEST determinism, `GroupShared` carries a `#[cfg(test)] monitor_paused: std::sync::atomic::AtomicBool` field (PER-INSTANCE — parallel tests each pause only their own guard; no global state) consulted before requesting cleanup, and tests manipulate it through a scoped reset guard (`struct PauseGuard<'a>(&'a AtomicBool)` whose `Drop` resets to false) so a panic cannot leave a monitor paused.
7. Implement the sync cleanup core as TWO functions to avoid recursive locking: `cleanup_locked(wait: Option<Duration>, reap: ReapMode) -> Result<(), BridgeError>` (ASSUMES `cleanup_exec` is already held by the caller — the body: `libc::kill(-pgid, SIGTERM)` → if `wait` is `Some(grace)`, bounded non-reaping bridge wait (blocking `waitid(P_PID, bridge_pid, WEXITED|WNOHANG|WNOWAIT)` poll loop with 10 ms sleeps, bounded by grace — blocking is acceptable: the thread is either the dedicated monitor thread or a `spawn_blocking` worker) → unconditional `libc::kill(-pgid, SIGKILL)` → `*pgid = None` (invalidate BEFORE any reap) → reap bridge then watchdog: `ReapMode::Blocking` loops `Child::try_wait()` with 10 ms sleeps bounded by 5 s per child (try_wait is sync — works with NO runtime), a reap timeout returns `Err(BridgeError::Supervision("reap timed out post-KILL".into()))` after logging (log-policy: system-broken) so a successful completion always implies both reaped; `ReapMode::NonBlocking` does a single `try_wait()` per child and returns) and the lock-taking wrapper `cleanup_sync(wait, reap)` which acquires `cleanup_exec` then delegates. Expose `GroupShared::stop_group(grace: Duration)` as the async façade: `tokio::task::spawn_blocking(move || cleanup_sync(Some(grace), Blocking)).await?` (GroupShared is Send: Arc + std Mutexes + tokio Children). No group signal is issued when `pgid` is `None`; the stop flag is set at the start of every cleanup so the monitor stands down.
8. Implement `Drop for GroupGuard` (synchronous context — NEVER awaits, works with or without a live runtime): `try_lock` on `cleanup_exec`; if contended (a cleanup is in flight on the monitor thread or a spawn_blocking worker) do nothing further — the in-flight cleanup owns the sequence. If acquired: call `cleanup_locked(None, NonBlocking)` DIRECTLY with the held guard (never re-acquire — recursive `cleanup_sync` would deadlock on the non-reentrant std Mutex). NEVER `start_kill()` on unix: a bare-PID signal is forbidden anywhere in this module (the group KILL already covered live members before invalidation). Dropping the guard closes `write_end` (EOF fires the watchdog path when the group outlives the guard), releases the strong `GroupShared` reference (the monitor thread's `Weak` fails to upgrade and the thread exits), and sets the stop flag so the monitor thread never outlives the guard by more than one poll interval.
9. Expose `#[cfg(test)] pub(crate) fn watchdog_pid(&self) -> Option<u32>` for UNIT tests in `src/group.rs` (cfg(test) items are invisible to integration builds; integration evidence tests assert via `running_members()` tokens instead).
10. Add `BridgeError::Supervision(String)` to the `BridgeError` enum in `src/process.rs` with `#[error("Bridge supervision error: {0}")]`; fix any non-exhaustive matches the compiler reports (the repo's own match sites only — run `cargo build -p camel-bridge` to enumerate).
