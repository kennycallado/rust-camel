# Design: mock-expectation-and-uri-surface

## Approach

Four additive moves inside `crates/components/camel-mock/src/lib.rs`
(with opportunistic splits along the way):

1. **Count expectations.** `MockExpectations` gains
   `expected_count: Option<usize>` and `minimum_count: Option<usize>`.
   `MockEndpointInner::expect_count(n)` sets exact;
   `expect_minimum_count(n)` sets minimum; both may coexist (both are
   enforced). This is an additive branch — body/header/regex checks
   are untouched (evaluation-order and latch rules live in move 2).

2. **Non-panicking surface.** New public API:
   `pub async fn try_assert_satisfied(&self) -> Result<(), MockAssertionError>`
   and `#[non_exhaustive] pub enum MockAssertionError` implementing
   `std::error::Error + Display`. Payloads (body details pre-formatted
   via `format!("{:?}", body)` so `Display` reproduces today's `{:?}`
   text byte-identically):
   - `CountMismatch { endpoint, expected, actual }`
   - `MinimumCountNotMet { endpoint, minimum, actual }`
   - `BodyCountMismatch { endpoint, expected, actual }`
   - `BodyMismatch { endpoint, index, expected, actual }`
   - `BodyNotFound { endpoint, expected }` (any-order)
   - `HeaderNotFound { endpoint, key, value }`
   - `HeaderRegexNotMatched { endpoint, key, pattern }`
   - `InvalidHeaderPattern { endpoint, key, pattern, source }`
   Every assertion branch maps to exactly one variant: exact count →
   `CountMismatch`; minimum count → `MinimumCountNotMet`;
   expected-bodies-count ≠ received-count (today `lib.rs:481`) →
   `BodyCountMismatch`; ordered body[i] mismatch (`lib.rs:512`) →
   `BodyMismatch`; any-order body not found (`lib.rs:503`) →
   `BodyNotFound`; header value not found (`lib.rs:524`) →
   `HeaderNotFound`; regex not matched (`lib.rs:538`) →
   `HeaderRegexNotMatched`; regex compile failure (`lib.rs:539`,
   today an inline panic) → `InvalidHeaderPattern` (does NOT trip the
   latch — a malformed expectation is a caller programming error, not
   a mismatch). Single evaluation path: one internal
   `async fn evaluate_expectations(&self) -> Result<(), MockAssertionError>`
   fetches the received snapshot, performs ALL checks, and trips the
   fail-fast latch (existing `set_fail_fast_on_mismatch` gating) on
   mismatch-class errors before returning `Err` — one latch call site,
   no parity drift. `assert_satisfied` calls it and panics with
   `panic!("{e}")` on `Err`; `try_assert_satisfied` returns the `Err`.

3. **URI surface.** Keep the controlbus pattern exactly: the
   `skip_impl` metadata descriptor (`camel-controlbus/src/metadata.rs`)
   gains five `#[uri_param]` entries — `retain`, `copy`, `failFast`,
   `expectedCount`, `anyOrder` (canonical keys only, no aliases).
   `create_endpoint` parses manually from `parts.params` (as controlbus
   does at `lib.rs:121`): `retain: usize >= 1` (reject 0 and
   non-numeric), `copy`/`failFast`/`anyOrder` as strict booleans
   (reject non-boolean), `expectedCount: usize >= 0`.
   Precedence: URI param present → overrides component `MockConfig`
   field; absent → `MockConfig` value; absent `expectedCount` → no
   count expectation. Per-name registry keeps first-creation-wins
   semantics (documented on the component). `expectedCount` maps to
   `expect_count()` on the fresh inner — recorded, never consulted by
   the producer. A catalog parity test (same shape as controlbus's
   `uri_options` test) locks metadata ↔ parser agreement;
   `cargo xtask schema` regenerates the catalog.

4. **`exchange(idx)` hardening.** Guard with
   `tokio::runtime::Handle::try_current()`: on `Ok(CurrentThread)`,
   panic immediately with a message naming the remedy
   (`#[tokio::test(flavor = "multi_thread")]` or the async accessors
   `get_received_exchanges`/`await_exchanges`); on `Ok(MultiThread)` or
   `Err` (no runtime), fall through to the existing `block_in_place`
   path unchanged — the guard only intercepts the deadlock case. No
   async signature change — the 47 inline tests keep their call shape.

**Count semantics.** Count expectations evaluate over the currently
retained snapshot (bounded by `max_retained`), not the total ever
received; count checks run before body checks and short-circuit. A
catalog note documents that `expectedCount` above `retain` can never
satisfy.

**Opportunistic split (ruling Q6):** while editing these regions, move
`MockEndpointInner` assertion logic to `assert.rs`, expectations to
`expectations.rs`, keep `lib.rs` as component/endpoint facade +
re-exports (pub surface unchanged). Only where already edited.

## Affected crates

- `camel-mock`: all source changes + tests.
- Schema/catalog artifacts regenerated by `cargo xtask schema` from the
  new metadata (no other crate's code changes; camel-cli already
  registers the component).

## Architecture boundaries

- **Data/control plane**: producer stays `Service<Exchange>` sink-only;
   no lifecycle op crosses `call()` (ADR-0001). `expectedCount` is
   never wired into `poll_ready`/`call` — the inertness guarantee.
- **Components**: URI parsing lives in `create_endpoint` exactly as
   controlbus does; no RuntimeQueryBus/IPC surface is touched
   (ADR-0002/0045 ceiling respected; frozen invariant for change #2:
   in-process harness via `get_endpoint` Arc, which stays `pub`).
- **Runtime/DSL**: zero changes — camel-cli registration already
  exists; YAML `to: mock:x?...` flows through existing endpoint
  creation.
- `MockAssertionError` does not depend on `CamelError` variants beyond
  what `Display` needs — it is an assertion-domain type, not a
  transport error.

## Alternatives considered

- **Make `exchange(idx)` async** — correct but breaks all 47 inline
  tests' call shape for no functional gain; rejected for churn. The
  chosen guard uses `Handle::try_current()` (not `current()`), which
  never panics outside tokio and only intercepts `CurrentThread`.
- **Parse URI params via the UriConfig macro's generated
  `parse_uri_components` instead of manual `parts.params.get`** —
  viable, but manual parsing keeps the controlbus shape the ruling
  named (controlbus retains `skip_impl` with bespoke parsing per
  CONTEXT-MAP.md) and avoids macro default-kind subtleties on
  `Option<usize>`; the parity test enforces agreement either way.
- **Enforce `expectedCount` via producer-side counting** — rejected
  (e_opus condition b): a metadata hint must never drop live traffic.
- **Bundling the `camel test` testkit here** — rejected by e_opus
  2026-08-20 re-consultation; change #2 stays separate and gated.
