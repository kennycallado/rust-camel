## camel-component-grpc — consumer cancellation safety

### Task 1.1: cancellation-safe permit acquisition helper + UNAVAILABLE reply helper

**Files:**
- `crates/components/camel-component-grpc/src/consumer.rs` (modified)

**Steps:**
1. Add a private enum `PermitWait` with variants `Granted(tokio::sync::OwnedSemaphorePermit)` and `Cancelled` near the other private types (below `GrpcRequestEnvelope`).
2. Add a private async fn `acquire_permit_cancel_safe(sem: std::sync::Arc<tokio::sync::Semaphore>, cancel: tokio_util::sync::CancellationToken) -> Result<PermitWait, CamelError>` that runs `tokio::select! { biased; _ = cancel.cancelled() => Ok(PermitWait::Cancelled), permit = sem.acquire_owned() => permit.map(PermitWait::Granted).map_err(|_| CamelError::ChannelClosed) }`.
3. Add a private fn `reply_unavailable(envelope: GrpcRequestEnvelope)` that consumes the envelope: for `Unary`/`ClientStreaming` variants send `GrpcReply::Err(tonic::Status::unavailable("consumer shutting down"))` on the oneshot `reply_tx` with `let _ =` (best-effort); for `ServerStreaming`/`Bidi` variants call `reply_tx.try_send(GrpcStreamItem::Error(tonic::Status::unavailable("consumer shutting down")))` and ignore the result. Add a `debug!` log with `path = "grpc consumer reply unavailable on shutdown"` style context where a path is not available; a plain fixed message is acceptable since the envelope carries no path.
4. Write the unit tests listed below in the existing `#[cfg(test)] mod tests` section of `consumer.rs`. Run them: the `permit_wait_cancel_safe_*` and `reply_unavailable_*` tests must pass after steps 1-3 (they do not depend on the loop restructure).

**Tests:** (executable spec)

- `permit_wait_cancel_safe_returns_cancelled_on_token_cancel`: `Semaphore::new(1)` whose permit is already owned (`let _held = sem.acquire_owned().await.unwrap()`), fresh token; spawn `acquire_permit_cancel_safe` on a task, then `token.cancel()` → task output is `Ok(PermitWait::Cancelled)` within `timeout(500ms, ..)`.

### Task 1.2: identity-owned dispatch registration guard

**Files:**
- `crates/components/camel-component-grpc/src/consumer.rs` (modified)

**Steps:**

2. Add an associated fn `arm(dispatch: GrpcDispatchTable, path: String, env_tx: mpsc::Sender<GrpcRequestEnvelope>) -> Self` setting `armed: true`.
3. Add a private fn `remove_owned_entry(table: &mut tokio::sync::RwLockWriteGuard<'_, std::collections::HashMap<String, crate::server::GrpcDispatchEntry>>, path: &str, env_tx: &mpsc::Sender<GrpcRequestEnvelope>)` that removes `path` from `table` ONLY when the stored entry's sender `same_channel(env_tx)`; this is the identity check (`GrpcDispatchEntry` is the `pub(crate)` tuple alias in `server.rs`).
4. Add `async fn cleanup(&mut self)` on the guard: acquire `self.dispatch.write().await`, call `remove_owned_entry`, then set `self.armed = false` while still holding the lock (no `.await` between removal and disarm).
5. Implement `impl Drop for DispatchRegistrationGuard`: if `!self.armed` return; first try `self.dispatch.try_write()` — on `Ok(mut table)` run `remove_owned_entry` synchronously and return; on `Err(_)` call `tokio::runtime::Handle::try_current()` and on `Ok(handle)` spawn a task that acquires `dispatch.write().await` and runs `remove_owned_entry`; on `Err(_)` (runtime teardown) do nothing — the entry's sender is closed once the consumer's `env_rx` drops and Task 1.3's insert replaces it.
6. Write the unit tests listed below. They must pass after this task (guard is standalone).

**Tests:** (executable spec)
