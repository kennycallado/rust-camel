# Design: http-query-wire-fidelity

## Layer model and decisions

Three layers, each owning one decision:

1. **camel-endpoint `UriComponents`** (crates/camel-endpoint/src/uri.rs) — ADDITIVE `raw_query: Option<String>`, captured verbatim at parse (uri.rs:124-133 region). The e_opus ordered-Vec re-type of `params` is REJECTED (e_glm: dedup-loss refuted at uri.rs:152-157; the ripple through every `UriConfig` derive buys nothing). Reconciliation of the two URI layers' repeated-key stories: **structured view strict** (duplicate keys fail `parse` loudly — unchanged), **raw view verbatim** (raw bytes preserved exactly as authored; redaction classification for display per ADR-0051 happens at the display layer, never at capture). This mirrors camel-api `EndpointUri` (endpoint_uri.rs:25-33) which already holds scheme/path/params + raw query. **Compatibility**: `UriComponents` is an exhaustive public struct (uri.rs:8-16) — every in-repo struct literal is updated in-change; external exhaustive literals break at the next minor boundary (documented in the release notes). camel-endpoint also EXPORTS one helper for downstream consumers: the raw-pair iterator `raw_query_pairs(&str) -> Result<Vec<(decoded_key, raw_span)>, CamelError>` (built on `split_query_pairs`, uri.rs:185-217; keys percent-decode fallibly, values never decode) so filters can match decoded keys against percent-encoded authoring (e.g. `connect%54imeout` decodes to `connectTimeout`) — with unit tests for encoded option keys and malformed escapes.

2. **camel-http producer serialization** (`resolve_url`, crates/components/camel-http/src/lib.rs:2434-2508) — **Data flow**: `HttpEndpointConfig` gains `raw_query: Option<String>`, populated in `from_uri`/`from_components` from `UriComponents.raw_query`; `resolve_url` consumes that field. **Query-source precedence** (existing semantics, made explicit): `bridgeEndpoint` bridging > `CamelHttpUri` full-URI override > `CamelHttpQuery` header (verbatim — the source appends it verbatim today, lib.rs:2468-2475/2492-2498; it is NOT a structured fallback) > endpoint `raw_query` as the base query > programmatic `query_params` (the ONLY structured path, RFC-3986-minimal, `%20` — never `+` — for spaces). **Provenance (e_opus-adjudicated)**: `from_uri` STOPS auto-populating `query_params` from URI leftovers (the collection block at lib.rs:326-330 is deleted) — `raw_query` is the SOLE carrier of authored pairs; `query_params` is re-typed `HashMap<String,String>` → `Vec<(String, String)>` so programmatic declaration order is real (tiny re-type: zero programmatic writers today). Merge: raw pairs (minus consumed options) in authored order, then programmatic entries whose key is absent from raw, in declaration order — authored keys always win. **Option-consumption metadata**: `connectTimeout` is stripped by the handwritten list today and silently dropped (`HttpEndpointConfig` has no such field; the `connect_timeout_ms` at lib.rs:2085 belongs to the global `HttpConfig`, not the endpoint) — it is PROMOTED to a metadata-only `#[uri_param]` on the private mirror `HttpEndpointUriConfig` (lib.rs:377) so the predicate consumes it exactly as before (parity pin at lib.rs:8998 updates 20→21; `cargo xtask schema` regenerates; no wiring into `HttpEndpointConfig`/`build_client`). `cookieHandling` needs no promotion: `from_uri` rejects it loudly (lib.rs:267-269) so it never reaches the serializer. **Raw path**: when `raw_query` exists, emit its bytes minus consumed option keys, using the exported raw-pair iterator; option-key consumption has a SINGLE metadata-driven owner (ADR-0041 `uri_options()`): the sole authority for OUTBOUND option filtering — the raw filter consults it at runtime — while `from_uri`'s manual typed parsing (`skip_impl`, lib.rs:181-330) stays direct and unchanged. The handwritten `HTTP_CAMEL_OPTIONS` key list (lib.rs:155-179) is removed. Wrappers and authored escapes survive as authored; a raw byte forbidden in a query component (space, `#`, non-ASCII) produces a resolve error — never silent re-encoding (this bounds "byte-for-byte" to wire-legal authored bytes). Empty query (`?` with no pairs) captures as `Some("")` and is preserved; all-options-consumed yields no query component at all. `.expect` on `url::Url::parse` at lib.rs:2445/2500 → propagate as producer error (rc-ph7z2); malformed operator input must never panic the producer task.

3. **camel-integration-test lane key + diagnostics** — lane key stays **strict wire bytes** (`path_and_query`, adapters.rs:268-271, http.rs:752-758): a canonical-key alternative would have masked the producer bug this change fixes (two-expert consensus). Once the producer is wire-faithful, declared `from:` URIs with queries become receivable. Diagnostics land with the serializer, not after: (a) receive-timeout error lists wire paths that DID arrive in the lane group (adapters lane registry); (b) partner-count-mismatch detail prints recorded paths (runner.rs:739-754 today prints counts only); (c) `ParsedTarget` silent `/` fallback (http.rs:343-345) becomes an apparatus-class error. **Redaction**: harness diagnostics use a POSITIVE secret rule — a query value is masked (as `***`) only when its key matches a secret-marked `UriOption` in scheme `http`'s `ComponentMetadata` (camel-http marks `authUsername`, `authPassword`, `authBearerToken`). Unknown keys stay visible because harness diagnostics are apparatus-internal and exist to show operators their wire bytes; ADR-0051's fail-safe blanket masking would render every mismatch diagnostic useless (`/api?x=***`). ONE entry point (conductor-verified call graph): `PartnerRouter::set_secret_query_keys(Vec<String>)` propagates to the router-stored set (read by `partner_mismatch_detail` rendering), the router-owned `ClientLane` (`await_parked` timeout site, http.rs:528-546), and every boxed adapter via a default-noop `PartnerAdapter::set_secret_query_keys` trait method (HTTP override feeds the arrivals-lane timeout site, http.rs:354 region). The CLI makes ONE call post-boot pre-run (scenario.rs :435-:446, `ctx.component_metadata("http")` → `.uri_options` field secret keys → router), because `HttpPartner` construction is PRE-boot (:185-199) and partners are already boxed as `dyn PartnerAdapter` by injection time. Change A merges first (human-approved), eliminating the wave-B sequencing risk.

## ADR / spec anchors

- ADR-0069 §5 (partner-side normative proof — bytes must be assertable) and §4 (same composition root; untouched here).
- ADR-0051 redacting wrappers: classification unchanged; the serializer must neither unwrap nor double-encode.
- ADR-0041 amendment (`uri_options` single source) — consumed-option key set must come from the same metadata, not a hand-written list.
- Canonical specs touched: `endpoint-uri`, `http-emission-correctness`, `integration-tier` (delta files in this change).

## Boundaries

Data-plane producer path + test harness only. No control-plane, no consumer emission policy change. camel-endpoint change is additive in behavior but is an ACCEPTED SOURCE-COMPATIBILITY BREAK: the new `UriComponents` field breaks every exhaustive struct literal — all in-repo literals updated in-change, external literals break at the next minor boundary (matches proposal risk budget).

## Test strategy

- camel-endpoint unit: parse captures raw bytes (incl. `%2C`, `:`, authored order); duplicates still rejected; absent query → None.
- camel-http: extend the pinned producer tests (lib.rs:3794 region) — order/bytes preserved end-to-end; consumed options stripped (including a query that is ALL options → no `?` in the result); bare `?` empty-marker preserved distinctly; RAW wrapper text preserved as authored (not re-encoded, not unwrapped — this is the rc-g4isv regression test); programmatic fallback deterministic; malformed URL → error not panic (rc-ph7z2 test).
- camel-integration-test: scenario-level — query-bearing partner receive matches after fix; receive-timeout message lists arrived paths; count-mismatch message lists recorded paths; empty harness path → apparatus error.
- Existing tests pinning the OLD rewritten format are updated in this change (expected churn, reviewed task-by-task).

## Phasing

Single-phase change, three task clusters by crate (endpoint → http → harness), serialized because each layer consumes the previous one's field/behavior.
