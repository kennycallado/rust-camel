# Design: business-error-model

## Approach

Follow the Apache Camel error mechanics this framework already has (`on_exceptions`, `doTry`/`catch`, `pipeline_error_to_reply`) and add one runtime envelope plus the surfaces that raise, match, expose, and map it. The envelope is a new `CamelError` variant; raising is a new declarative step; matching extends the two existing clause grammars with two new field names; Simple gains three exception paths; HTTP gains a mapping table threaded into the existing reply finalizer. No new error-handling subsystem: every behavior rides the existing clause evaluation, disposition, and redelivery machinery (ADR-0019, ADR-0024, ADR-0025).

## Affected crates

- camel-api: `CamelError::Business` with the redacting `RedactedJson` data newtype, `classify()`, `variant_name()`, the `HttpErrorMapping` type (route-level, not on `ErrorHandlerConfig`).
- camel-dsl: `throw` step (model, AST, compile), catch-clause fields, `DeclarativeOnException.code`, the route-level `http_error_mapping` field (`RouteDslRoute`/`DeclarativeRoute`, serde-skip fence), rest `error_mapping` lowering, vocabulary list.
- camel-processor: error-handler clause matching, redelivery skip, log policy.
- camel-language-simple: parser + evaluator for the exception paths (`code`, `business_kind`, `data`; `kind` arrives via the rc-7qv90 prerequisite).
- camel-http: consumes `HttpErrorMapping` through the `pipeline_error_to_reply` parameter; default kind map.
- camel-core: installs the mapping snapshot on the consumer registration seam (`ConsumerContext`) at route registration; camel-core / camel-tests host propagation and end-to-end tests.

## Architecture boundaries

- DSL (camel-dsl): all authoring surface; compiles to the same `RouteDefinition` path as YAML and JSON (ADR-0017, ADR-0026).
- Runtime/Processor: clause matching and dispositions stay in the existing error handler. The breaker exclusion covers both implementations, `CircuitBreakerService` and `CircuitBreakerGate`; the tracer's error metrics apply the same exclusion as observability (metrics are not breaker state).
- Languages: Simple reads the exchange error only; it sets no properties and mutates nothing (language-value-boundary).
- Components/transport: camel-http consumes the mapping through its reply finalizer; the mapping type itself lives in camel-api so no dependency cycle appears. No other transport changes.

## Phases

### Phase 1: core business error model
- **Goal:** raise, catch, expose, and enforce policy for `CamelError::Business` without HTTP.
- **Dependencies:** bd `rc-7qv90` (`${exception.kind}` parse/evaluate) MUST land before this phase's Simple task — owner-set prerequisite (Q2); it is not implemented here.
- **Externally-visible types/interfaces:** `CamelError::Business` (+`RedactedJson`), `throw` step, catch `code`/`business_kind`, `on_exceptions` `code`, `${exception.code|business_kind|data.*}` (`${exception.kind}` parse lands with bd `rc-7qv90`, prerequisite).
- **Deliverable:** camel-api/dsl/processor/simple changes with tests.
- **Exit-criteria:** throw/catch/Simple/policy/async-boundary tests pass; vocabulary guard updated.

### Phase 2: HTTP mapping and rest inheritance
- **Goal:** mapped, safe-closed HTTP replies; `rest:` inheritance.
- **Dependencies:** Phase 1. Note: the reply arm also closes bd `rc-7lkp2` (Ok-with-error never 2xx) as part of the mapping arm; rc-7lkp2 stays the tracking issue.
- **Externally-visible types/interfaces:** `http_error_mapping`, rest `error_mapping`, `pipeline_error_to_reply` parameter.
- **Deliverable:** camel-http + rest lowering with tests; end-to-end demo route test.
- **Exit-criteria:** mapped statuses, 500 safe closure, no-2xx, body-only-mapping tests pass.

## Alternatives considered

Per-row rejected alternatives appear in the decision table. Two whole-feature alternatives were rejected: (a) DDD-typed error hierarchy per domain — rejected as a type system, not integration plumbing (the demo team's own review); (b) stringly `ProcessorError` + `message_contains` matching — this is today's state; it is the problem statement.
