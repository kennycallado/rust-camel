# Design: redb-cache-resource-limits

## Approach

The redb page-cache budget becomes an explicit, mandatory operator decision at every
layer, and the sweep cadence becomes configurable. Delivered in two phases.

**Core (Phase 1, camel-core `cache/redb.rs`).** `RedbCacheRepository::new` takes a
required `cache_size: usize` (matching redb 4.1.0 `Builder::set_cache_size(&mut self,
bytes: usize)`, vendored `db.rs:1161`). Inside the existing `spawn_blocking` open block,
the database opens through `redb::Builder::new().set_cache_size(bytes).create(path)`.
There is no `Option`, no fallback: redb's 1GiB default (`db.rs:1126`) must be
unreachable. redb exposes no cache-size getter, so the repository stores its
`cache_size` in a field that in-crate tests assert on — that is the propagation seam;
the three-line builder call is covered by code review plus the round-trip smoke test.

**Config (Phase 1, camel-config).** `CacheRepoConfig` gains `cache_size: Option<String>`
(required at validation when `backend = "redb"`) and `sweep_interval: Option<String>`.
A private `parse_byte_size` helper accepts plain integers (bytes) and suffixes
`B`, `KB`/`KiB`, `MB`/`MiB`, `GB`/`GiB` — case-insensitive, decimal = 10^3 and
binary = 2^10 steps, values that overflow `usize` are rejected. No new dependency:
humantime covers durations; four suffixes do not justify a crate. Validation (extending
the existing `cache_repo` block in `config.rs`): redb backend requires `cache_size`,
rejects zero `sweep_interval` (`tokio::time::interval` panics on zero), and rejects
malformed `cache_size`/`sweep_interval`/`stale_retention` with field-naming errors —
no silent defaults. Wiring in `context_ext.rs` parses and propagates errors (defense in
depth, unreachable post-validation), replaces the hardcoded `Duration::from_secs(3600)`
with the parsed `sweep_interval` defaulting to 1h, and passes `cache_size` through.

**Guardrail (Phase 1, camel-core).** `memory_limit_from_paths(v2_path, v1_path)` —
pure, temp-file-testable — reads cgroup v2 `memory.max` (`"max"` and unparseable content
fall through) then v1 `memory.limit_in_bytes` (v1 sentinel values above 16 TiB count as
unlimited). Called with the real `/sys/fs/cgroup/...` paths at repository open; when the
effective cache size exceeds the detected limit, one `tracing::warn!` names both
numbers. Diagnostic only. Tests capture tracing output through the repo's existing
log-capture pattern; no test reads or depends on a real cgroup.

**ADR-0056 amendment (Phase 1, docs).** Decision 6 keeps its original text and gains a
dated note (2026-08-18): the 60s default never shipped (code hardcoded 1h);
`sweep_interval` now makes it configurable; the default stays 1h because an O(N) sweep
over a large persistent cache costs more than delayed reclamation. The book HTML is a
build artifact regenerated by the book pipeline.

**Dead-config hygiene (Phase 2, camel-config).** Validation rejects fields that do not
apply to the configured backend: `path`, `stale_retention`, `max_entries`, `cache_size`,
`sweep_interval` with `backend = "memory"`; `max_capacity` with `backend = "redb"`.
Prerequisite serde fix: `default_stale_retention()` returns `Some("168h")` today, which
materializes omitted `stale_retention` as a set field — change the serde default to
`None` (aligning the `Default` impl, which already uses `None`), keep the 7d fallback
in wiring after validation. Delta requirements land under the `dead-config-policy`
spec domain.

## Affected crates

- `camel-core`: `cache/redb.rs` — required `cache_size` parameter, builder-based open,
  cgroup detection + warn, `cache_size` field for the test seam. Unit tests: parser
  edges, cgroup paths, limit comparison, round-trip with explicit size.
- `camel-config`: `config.rs` — new fields, `parse_byte_size`, validation extensions
  (Phase 1 strict parse; Phase 2 cross-backend); `context_ext.rs` — wiring. Unit tests
  per scenario.
- `examples/cache-example` (and any in-repo constructor caller): updated for the new
  required parameter.
- Docs only: `docs/adr/0056-cache-repository-port.md` dated amendment.

## Architecture boundaries

Runtime + config-plane only; DSL, components, data plane untouched. ADR-0056
Decision 6 respected: no `sweep()` on the trait — we parameterize sizing and cadence
the backend already owns, plus a diagnostic. `CacheRepoConfig` remains the single
config seam mirroring `idempotent_repo`. Phase 2 enforces the dead-config-policy
spec's fail-closed principle on this section.

## Phases

### Phase 1: close the OOM class (incident fix)

- **Goal:** No code path reaches redb's 1GiB default cache; budgets are explicit;
  guardrail warns on container-limit conflicts.
- **Dependencies:** none (redb 4.1.0 builder API verified in vendored source).
- **Externally-visible types/interfaces:** `RedbCacheRepository::new` required
  `cache_size: usize` parameter (breaking for programmatic callers);
  `CacheRepoConfig.cache_size` (required for redb) and `sweep_interval`.
- **Deliverable:** eip-cache delta requirements satisfied; ADR amendment; updated
  examples.
- **Exit-criteria:** all Phase 1 scenarios pass; a redb config without `cache_size`
  fails validation; no caller compiles without an explicit size; `cargo clippy -D
  warnings` and `cargo fmt --check` clean on affected crates.

### Phase 2: dead-config rejection on `cache_repo`

- **Goal:** Fields that don't apply to the configured backend fail validation
  fail-closed.
- **Dependencies:** Phase 1 merged on the branch (serde `None` default builds on the
  strict-parse validation).
- **Externally-visible types/interfaces:** none new — validation behavior only.
- **Deliverable:** dead-config-policy delta requirements satisfied.
- **Exit-criteria:** each cross-backend mismatch scenario passes; omitted
  `stale_retention` still yields the 7d wiring fallback for redb; memory configs with
  no extra fields validate unchanged.

## Alternatives considered

- **Optional `cache_size` + warn-only** (original draft): rejected at spec-bless — it
  leaves the incident reachable for anyone who doesn't read logs. Mandatory sizing
  closes the class.
- **Default `cache_size` (e.g. 512MiB) instead of required:** rejected — a silent
  default is right for some deployments and wrong for others; an explicit operator
  decision is the point.
- **Options-struct constructor refactor:** rejected — breaks every caller for zero
  functional gain; revisit if the constructor grows further.
- **`byte-unit`/`humansize` dependency:** rejected — trivial parser, suffix semantics
  pinned by test.
- **Sweep cost reduction (expiry secondary index):** out of scope — storage schema
  migration; bd follow-up.
- **`cache_size` for idempotent repo + lifecycle journal:** same defect class,
  separate blast radius; bd follow-ups.
